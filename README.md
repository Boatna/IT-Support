# 🛠️ IT Support Helpdesk & IT Control Center

ระบบแจ้งซ่อมและบริหารจัดการงานเทคโนโลยีสารสนเทศ (IT Service Desk & Control Center)
เชื่อมต่อฐานข้อมูล Google Sheets ผ่าน Google Apps Script Web App

---

## 📁 โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
| :--- | :--- |
| **`Code.gs`** | Backend (Google Apps Script): API, บันทึก Sheet, อัปโหลดรูปไป Drive, ส่งอีเมล, ตรวจ PIN/Token |
| **`Index.html`** + `app.js` | หน้าพนักงาน (แจ้งซ่อม / ติดตามสถานะ) |
| **`dashboard.html`** + `dashboard.js` | IT Control Center (ล็อกอิน PIN, สถิติ, กราฟ, จัดการ Ticket) |
| **`style.css`** | CSS ของทั้งสองหน้า |

> `Code.gs` อยู่บน Google Apps Script เท่านั้น ส่วนไฟล์ที่เหลือโฮสต์บน GitHub Pages (หรือเว็บเซิร์ฟเวอร์ใดก็ได้)

## 📊 ชีตใน Google Sheet

| ชีต | รายละเอียด |
| :--- | :--- |
| `IT_Requests` | เก็บ Ticket 23 คอลัมน์ (สร้างให้อัตโนมัติถ้ายังไม่มี) |
| `Employee_Data` | รายชื่อพนักงาน อ่านจากหัวคอลัมน์: รหัสพนักงาน, ชื่อ-นามสกุล, แผนก, ตำแหน่ง, Plant, อีเมล, เบอร์โทร, เลขทะเบียน Asset — **แถวที่ไม่มีรหัสพนักงานจะถูกข้าม** (ชีตจริงมีแถวสูตรว่างต่อท้ายถึงแถว 1014 ลบทิ้งได้) |
| `IT_Staff` | ช่าง IT และ **PIN รายคน** — A = ชื่อช่าง, B = PIN, C = สถานะ (ว่าง/`ใช้งาน` = ใช้ได้, `ปิด` = ระงับ) ระบบสร้างชีตนี้ให้อัตโนมัติ พร้อมชื่อตั้งต้นจาก `IT_STAFF_DEFAULT` (PIN เว้นว่างไว้ให้กรอก) |

**Ticket ID:** `IT` + `yyMMdd` + `-` + เลขรัน 3 หลักต่อเนื่องทั้งระบบ เช่น `IT260908-027` (ระบบหาเลขสูงสุดเดิม +1)

**คอลัมน์ `IT_Requests`:** Ticket ID · วันที่แจ้ง · รหัสพนักงาน · ชื่อ-นามสกุล · แผนก · ตำแหน่ง · Plant · เบอร์ติดต่อ · เลขทะเบียน · เลข Asset · ระดับความด่วน · หมวดหมู่ปัญหา · รายละเอียดปัญหา · เหตุผลที่ขอเครื่องใหม่ · ประเภทเครื่อง · โปรแกรมที่ติดตั้ง · รูปภาพแนบ · สถานะ · ผู้รับผิดชอบ · บันทึกการแก้ไข IT · แจ้งซ่อมภายนอก · รายละเอียดซ่อมภายนอก · อีเมลผู้แจ้ง

## 🚀 วิธี Deploy

1. เปิด Google Sheet ▸ **Extensions ▸ Apps Script**
2. วางโค้ดจาก **`Code.gs`** แทนที่โค้ดเดิมทั้งหมด แล้ว Save
3. เลือกฟังก์ชัน **`testSetup`** ▸ Run ครั้งแรก เพื่ออนุญาตสิทธิ์ (Sheet / Drive / Mail) — ระบบจะสร้างชีต **`IT_Staff`** ให้
4. เปิดชีต `IT_Staff` แล้วกรอก **PIN ของช่างแต่ละคน** ในคอลัมน์ B (อย่างน้อย 4 ตัวอักษร ห้ามซ้ำกัน) เพิ่มช่างได้โดยเพิ่มแถว
   - (ไม่บังคับ) **Script Properties** `IT_NOTIFY_EMAILS` = อีเมลทีม IT คั่นด้วย `,` ถ้าไม่ใส่จะส่งหาเจ้าของสคริปต์
   - Run `testSetup` อีกรอบเพื่อตรวจว่า PIN ครบ/ไม่ซ้ำ
5. **ซ่อมข้อมูลเก่า** (ทำครั้งเดียว): Run **`migrateLegacyDryRun`** ดูรายการที่จะแก้ใน log → ถ้าถูกต้อง Run **`migrateLegacyApply`** (ระบบสำรองชีตเป็น `IT_Requests_backup_...` ให้ก่อน)
6. **Deploy ▸ Manage deployments ▸ ✏️ Edit ▸ Version: New version ▸ Deploy**
   (Execute as: *Me* · Who has access: *Anyone*) — URL เดิมจะยังใช้ได้
7. ตรวจว่า `API_URL` บรรทัดแรกของ `app.js` และ `dashboard.js` ตรงกับ Web App URL

> ถึงยังไม่รัน migrate ก็ตาม Dashboard จะอ่านสถานะ/ผู้รับผิดชอบแบบเก่าได้ถูกต้องอยู่แล้ว และแถวจะถูกแก้ให้ถูกคอลัมน์เองเมื่อช่างกดบันทึกครั้งถัดไป

## 🔐 ความปลอดภัย

- Dashboard ใช้ **PIN รายคนจากชีต `IT_Staff` + Session Token** ที่ตรวจที่ฝั่งเซิร์ฟเวอร์ (อายุ 6 ชม.) ข้อมูล Ticket/สถิติ/รายชื่อช่าง/การอัปเดตทั้งหมดต้องมี token
- ระบบรู้ว่าใครล็อกอิน: แสดงชื่อที่มุม Dashboard และปุ่ม "รับงานนี้" ใช้ชื่อนั้นทันที
- PIN ไม่ถูกส่งออกทาง API ใดเลย แต่ **ใครมีสิทธิ์แก้ไข/ดู Google Sheet นี้จะเห็น PIN ได้** ควรจำกัดสิทธิ์ชีตให้เฉพาะผู้ดูแล หรือคลิกขวาแท็บ `IT_Staff` ▸ Protect sheet
- ใส่ PIN ผิดเกิน 5 ครั้ง ระบบล็อก 10 นาที (ตัวนับรวมทั้งระบบ)
- ช่างที่ลาออก: ใส่ `ปิด` ในคอลัมน์ C (ชื่อยังอยู่ในประวัติงานเดิม แต่เข้าสู่ระบบไม่ได้)
- ทางสำรอง: ถ้าตั้ง Script Property `IT_PIN` ไว้ จะใช้เป็น PIN กลางแบบเดิมได้ (ไม่ระบุตัวตน) — ลบทิ้งได้เมื่อใช้ PIN รายคนแล้ว
- ข้อมูลพนักงาน (ชื่อ/แผนก/ตำแหน่ง/Plant) ตอนบันทึก Ticket จะอ้างอิงจากชีต `Employees` ไม่เชื่อค่าจากเบราว์เซอร์
- ข้อควรทราบ: หน้าพนักงานเรียก `getEmployees` แบบสาธารณะ (รวมอีเมล) และ `getTickets` ตามรหัสพนักงาน โดยไม่ต้องล็อกอิน — เป็นการออกแบบเพื่อความสะดวก หากต้องการเข้มขึ้นควรผูกกับ Google Workspace login
- รูปที่แนบถูกตั้งเป็น "ทุกคนที่มีลิงก์ดูได้" เพื่อให้ Dashboard แสดงตัวอย่างได้ (ถ้าองค์กรจำกัดการแชร์ ระบบจะข้ามขั้นนี้)
